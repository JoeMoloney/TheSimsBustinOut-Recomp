## November 18 (end of day): NATIVE FIBERS IN THE RUNTIME → next: first non-leaf rewrite

- **Decision (user): option 2, fibers.** Implemented in PS2Recomp (local branch `sims-bustin-out-fixes`): `include/runtime/ee_native_calls.h` (`ps2x::native::runOnFiber`, `callGuest`), `src/lib/Kernel/EeNativeFiber.cpp` (ucontext fibers, 256 KiB stacks + guard page, pooled), `EeScheduler` members (`runNativeOnFiber`, `callGuestFromNative`, `resumeParkedNative`, `dropParkedNative`, `parkedNativeCount`, `m_parkedNative`). How it works: a native function that calls out parks its fiber keyed on (thread, invocation depth, return address); the callee runs on the normal scheduler path (may yield/block/unwind as usual); `run()` switches back into the fiber when the thread's pc reaches that return address. ## November 18 (later): THESEUS BATCH 1 — 27 rewrites live; non-leaf functions need a design decision

- **Batch 1 (17 most-called leaves) gated and shipped to the probe:** `Mem_Copy_00268588` (the game's memcpy, 801 call sites, **255,578 calls in 3 min**), `SmallAlloc_FreeToBin_00101d08` (free list of 16-byte size classes, table 0x3A45C0), `BitArray_Read_002ac6b8`, three `TypeTag_IsFlaggedTypeNN` checks (~32k calls each), `Stack_PeekFromTop`, `TwoSlot_Value`, `SByte3_*` (3-byte struct: set with s8 range check, copy x2, from 28.4 fixed point), `Flags_HasAll`, `Flags38_SetBit28`, `Mode_TryEnter` (globals 0x3F92B4..BC), `GlobalTable_EntryFieldC` (table 0x3F92C8), `Field584_PositiveElse5BC`. All 27 rewrites: PASS-ABI, callers ok (2,476 sites), 288/288 mutants. 180 s headless run: no errors, 16 of 27 called. Deferred: `0x2b5230` (tree map find, nil = 0x3A8AA8) and `0x12b108` (`_Rb_tree_increment`, GCC 2.95 layout) need a tree-building input rule; `0x39c618`/`0x39c660`/`0x3842a8`/`0x391cb0` are Sony SDK code (skipped).
- **Tool changes:** `aptr`/`alen N` rule kinds; `u32`/`int` give edge values; rule-set addresses compared every case; stub fingerprints access width; gate mutants skip `static_cast<>` brackets; `// gate: equivalent <token>: <reason>` skips only mutants producing <token>; `theseus.h` has `arg64/sarg64/read64/write64`.
- **Caller check ABI rule** (`caller_usage.py`): at `jalr`, syscalls and switch jumps, a scratch register not written since our call is dead. Survey: 42,912 calls x 16 scratch registers, 11 reads, all after no-return calls (the map runs into the next function) or in Sony SDK assembly. Direct callees and v0 returns are still followed.
- **⚠ DESIGN ISSUE for non-leaf rewrites:** PS2Recomp switches guest threads by **unwinding** (`GuestThread` holds only an `R5900Context`; `dispatchGuestBranch` checks `checkpointDue()` on every call; a blocked `WaitSema` also unwinds). The thread later resumes via `lookupFunction(ctx->pc)`, i.e. at the **internal resume slot of the original generated function**. A rewrite that calls out can therefore be resumed mid-way by the original code, which expects its own registers and stack frame. Leaves are unaffected. Sizes: leaves 39.5k of 759k instructions; non-leaf functions whose whole call tree never yields: 359 (9.8k insns), 1,146 (52k) if loops may run with time-slice yields held off; the remaining ~88% of the code can reach a yield. Options: (1) rewrites that keep the original's registers and frame at every call (harness checks state at each call); (2) runtime support: run a rewrite's callee on a host fiber/coroutine so a yield suspends the rewrite and the thread resumes into it (also what a Rust rewrite would need); (3) stick to yield-free call trees for now.

## November 18 (late): THESEUS PILOT — 10 rewrites gated and running in the game

- **Pipeline (`tools/theseus/`, design ported from Fable II):** `elfscan.py` (function list + assert-string evidence, shared), `inventory.py` (→ `out/theseus/functions.jsonl`: 11,186 functions, 759k instructions, 2,852 integer-only leaves), `difftest.py` + `harness/` (original vs rewrite on 200k random states), `caller_usage.py`, `gate.py`, `ship.py`, `theseus.h` (the `Guest` helper rewrites use), `progress.py`. The README has the command table.
- **Harness (`harness/difftest_harness.cpp`, `runtime_stub.cpp`):** links one generated function + one rewrite against a stub `PS2Runtime` (generated code only needs `dispatchGuestBranch`, `eeCheckpointDue` (always false), `Load*/Store*` for hardware addresses, syscall/break/trap/exception). Two 32 MiB RAMs preloaded with the ELF segment; 64 KB random window at 0x01000000; stack below 0x01F00000; gp = 0x3FFAF0. ABI compare: v0 low 32, s0-s7/gp/sp/fp/ra (128-bit), f20-f31, fcr31, pc, memory (window + stack + every `mem32`-ruled address per case, all RAM every 1,000 cases), hardware traffic fingerprint (address, width, value). Rules: `a0 ptr|u32|str N|wstr16 N|wstr32 N|…`, `mem32 <addr|@a0+off|*addr+off> <kind>`; `u32`/`int` give edge values (0xFFFF, 0x10000, 0xFFFFFFFF, …) a quarter of the time. Builds use the game's flags from `compile_commands.json`; objects are cached by a content hash (`.stamp`), never by mtime (an mtime cache once linked a negative-control rewrite into the real test).
- **Facts learned:** a plain `jr $ra` is `ctx->pc = $ra; return;` (the Return dispatch only exists under `PS2X_STRICT_RETURN_DIAGNOSTICS`). **v1 is never read after a call** in this game (survey of all 43,056 `jal` sites; ee-gcc returns even 64/128-bit values in v0), so the caller check treats v1 as dead at `jr $ra`. `ldl/ldr` and `lwl/lwr` pairs replace the register (not a read). The function map overstates some sizes (FUN_002c8538 is 3 instructions, the map says 34: unreachable padding follows).
- **bstring layout so far:** string +0 = rep pointer; rep +0 probably char data, +4/+8 length/capacity (stored by FUN_002c85e0), **+0xC reference count**; shared empty reps at 0x4564F0 (bstring.cpp) and 0x456500 (bstring2.cpp). `RegisteredObject_Construct_002cb4d8`: vtable 0x3E69A8 (slots 0, 0, 0x2CB510, 0x2CB580), list head gp-0x7764 (0x3F838C), next id gp-0x7760 (0x3F8390).
- **Gate result:** all 10 PASS-ABI, callers ok (165 call sites), mutants 110/110 killed. Two lines carry `// gate: equivalent` (a wider read whose result is truncated by the following write). Ledger: 10 rows `gated` (light green on the map).
