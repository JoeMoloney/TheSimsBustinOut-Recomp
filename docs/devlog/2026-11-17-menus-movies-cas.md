## Earlier on November 17: LANGUAGE MENU + AUTOSAVE NOTICE WORK ✅ → blocker was the IPU (now solved, see above)

Memory-service entries #586–#597 hold the details (addresses, struct offsets, evidence).

- **Root cause of the static front-end (FIXED, PS2Recomp runtime):** COP0 `Count` (`mfc0 $9`) is recompiled as a read of `ctx->cop0_count`, but nothing ever advanced it. The game's clock (`0x2908f8`: `(Count - base) / 294912000`) therefore stayed at 0, so the Apt Flash UI pump `0x233358(dt)` always got `dt = 0` and never advanced a frame: no Flash drawing, async `loadMovie` queue (`0x231d98`) never processed, `lmenu` never loaded, `menu_ready` never sent. Fix: `EeScheduler.cpp` file-local `syncCop0Count()` copies `m_eeCycle` into the running context's `cop0_count` in `accountCycles()`, `makeRunning()` and after an invocation is pushed. No regeneration needed. Ground truth came from PCSX2 via the `pcsx2-pine` MCP (same heap addresses; PCSX2 queue entries reach state 6, clock delta 40 ms).
- **Investigation trail, so nobody repeats it:** the memory card was not the blocker (only `sceMcInit` ran before the fix). Sema 18 is the quit signal (memory #502). It was not a rendering bug (GS stats showed only backdrop sprites) and not a slow timer (86 s of guest time, still static). Front-end state machine: manager `0x1567f08`, `+0x34` = current state; state 54 = language menu (waits for Flash `menu_ready`), state 0 = 3 s fade, state 1 = autosave notice, state 5 = after the memory-card check.
- **Visible run (user, keyboard):** the language menu renders (English/Dansk/Suomi/Norsk/Svenska, ✕ SELECT); the arrow keys move and X/Space selects; the autosave notice appears and X dismisses it; the memory-card check runs (`GetInfo` ports 0/1 OK, `GetDir` → -4 on a blank card).
