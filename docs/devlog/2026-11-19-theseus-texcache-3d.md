## November 19 (night): SPEED — decoded texture cache + SSE bilinear in the GS CPU backend

- **Change (PS2Recomp `sims-bustin-out-fixes`, uncommitted):** `gs_cpu_backend.h/.cpp`, `ps2_gs_memory.h/.cpp`. Textures are decoded to RGBA8 once, in 32x32 tiles on first use, keyed by TEX0 (tbp0/tbw/psm), texture size, TEXA, and for indexed formats cpsm/csm/csa + a CLUT generation (bumped in `LoadClutUnlocked`). Invalidation: `WriteVramUnlocked` bumps a generation per 8 KB VRAM page (`GSMem::PixelByteAddress`, new); an entry keeps (page, generation) for every page its tiles came from and is dropped at the start of a primitive (`PrepareTextureCache`, called in `DrawPrimitive` when TME) if one changed; a write in a format without a layout, `Reset`, and **TEXFLUSH** bump an epoch that drops all entries (decodes go through the old single-page buffer, which models the GS texture cache's staleness until TEXFLUSH; the test `TEXFLUSH must make the updated local-memory page visible` caught the missing flush). Limits: 64 entries, 8192 tiles (32 MiB), LRU. Coordinates outside the texture (REGION_REPEAT) take the old path. Bilinear: `lerpTexels` does the four channels in one SSE register with the same float operations in the same order as `lerpChannel` (bit-identical), and a fast path fetches the 2x2 texels straight from the tiles when the footprint is inside the texture and wrap is REPEAT/CLAMP.
